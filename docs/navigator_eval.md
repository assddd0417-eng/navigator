# Navigator 검증 결과

기업 3곳으로는 적중률이 의미가 없어서, 검증용 가상 기업 17곳을 더해 20곳 × 공고 5건 = 100쌍에 정답을 달고 쟀다.

- 데이터: `seeds/navigator_eval/corpus.json` (기업 111~127 + 시드 101~103, 공고는 시드 101~105)
- 실행: `cd backend && python -m app.navigator_eval all` (기록은 `eval_run`, `config.kind = NAVIGATOR`)
- 정리: `python -m app.navigator_eval clean` (111~127 비활성화. 화면·매칭 후보에서 빠짐)

## 무엇을 쟀나

| 항목 | 내용 |
|------|------|
| 판정 일치 | 쌍마다 적합/정보부족/부적격이 정답과 같은지 |
| 걸린 요건 일치 | 부적격이면 미충족 필수 요건, 정보부족이면 모르는 필수 요건 목록까지 같은지 |
| 상위 K 포함률 | 공고별 "꼭 검토할 기업"(정답)이 추천 순위 3위·5위 안에 드는지 |
| 후보 검색 포함 | 정답 기업이 벡터 후보 검색 단계에서 빠지지 않는지 |

정답 기업 = 판정이 적합 또는 정보부족이면서 요구기술 분야가 맞는 곳. 공고당 2~3곳, 모두 14건.

### 순위 — 참고값

담당자 화면은 적합 / 정보부족 / 부적격을 따로 나눠 각각 총점 순으로 보여 준다 (아래 문제 때문에 2026-11-11 변경). 정답 기업의 순위는 자기 판정 목록 안에서 센다.

| 지표 | 판정별 목록 | 한 줄 순위 (이전) |
|------|------|------|
| 정답 14건 상위 3 포함 | 100% | 85.7% (12건) |
| 정답 14건 상위 5 포함 | 100% | 92.9% (13건) |
| MRR | 0.798 | 0.595 |
| 적합 판정 정답(8건)만 상위 3 포함 | 100% | 100% |
| 후보 검색 포함 | 100% | 100% |

해시 임베더는 글자 조각이 겹치는 정도만 보므로 순위 수치는 참고용이다. 운영 모델(bge-m3)로 다시 재야 한다 (아래 "남은 일").

### 한 줄 순위의 문제 (고침)

이전에는 "판정 → 총점" 한 줄로 정렬해서, 분야가 맞는 정보부족 기업이 분야가 다른 적합 기업 뒤로 갔다.

- 공고 101: 113 한결통신(항재밍 모뎀, 신용등급만 없음)이 8위. 앞의 3~7위는 분야가 다른 적합 기업.
- 공고 105: 125 한국정밀소재(복합재)가 적합이라 2위, 분야가 맞는 101 한빛·113 한결은 3·5위.

담당자 화면을 판정별 목록으로 나눠, 113 한결은 공고 101 정보부족 목록 1위로 보인다. 부적격 목록은 접어 둔다. 매칭 결과의 `rank` 값(판정 → 총점)과 기업 쪽 화면은 그대로다.

## 전체 흐름 확인 (2026-11-17)

판정 규칙 말고, 기업 등록부터 참여 권유 수신 거부까지 실제로 이어지는지 확인했다. `tests/test_navigator_e2e.py` 가 같은 흐름을 돈다.

| 순서 | 확인한 것 |
|------|------|
| 1 | 새 기업 등록 → 등록 완료 메일, 등록 이메일이 알림 수신자로 바로 시작 |
| 2 | 회사 정보 입력, 참여 권유 동의 |
| 3 | 담당자가 공고문 붙여넣기 → 조건 뽑기(규칙) → 그대로 확인하고 공개 |
| 4 | 공개와 동시에 알림 메일·화면 알림, 담당자 발송 현황. 다시 공개·재발송해도 중복 없음 |
| 5 | 담당자 판정 실행 → 새 기업 적합 1위 |
| 6 | 참여 권유 메일(메모, 신용등급 값 없음) → 수신 거부 링크 → 동의 해제 |
| 7 | 기업 화면 추천·공개 조회(신용등급 요건 가림), 알림 수신 거부 |

실제 서버(`app.site`)에 로컬 SMTP 서버를 붙여 메일이 SMTP 로 나가는 것까지 봤고, 화면(등록 → 알림 탭, 공고 붙여넣기 → 조건 뽑기 → 공개, 담당자 알림 현황)도 브라우저로 따라갔다. 외부 SMTP(Gmail 등)로는 아직 안 보냈다.

이때 고친 것:

- 등록 화면은 "새 공고 알림 받을 이메일"을 받는데 수신자가 만들어지지 않아 알림이 안 갔다 → 등록 때 등록 이메일을 수신자로 넣음
- 알림·권유 메일과 공개 조회 문구가 "등록 이메일로 받은 링크"를 안내했는데, 등록 메일에는 링크가 없음 → "회사 정보 입력·수정"으로 안내
- "2. 지원대상: 중소기업 (기업부설연구소 …)" 같은 한 줄 제목을 구역 제목으로 못 읽어 기업규모·연구소 조건과 지원 대상이 빠짐, 요구기술은 규칙으로 안 뽑음 → 둘 다 뽑음 (실제 '26-1차 컨설팅 공고 결과는 그대로)
- 담당자 알림 현황에 받는 사람이 없어 같은 기업 수신자 2명이 같은 줄로 보임 → 가린 주소 표시

## 한계

- 기업·공고·정답 모두 합성이다. 정답은 판정 규칙을 아는 사람이 공고 요건을 읽고 손으로 달았다. 그래서 판정 100%는 "규칙이 의도대로 동작한다"는 확인이지 실제 공고에서의 정확도가 아니다. 실제 정확도는 공고문 요건을 사람이 옮겨 적을 때의 해석 차이와, 기업이 입력하지 않은 값에서 갈린다.
- 신용등급 자가입력(117, 119)도 등급만 맞으면 충족으로 본다. 실제로는 평가서 확인 전이므로 담당자 확인이 필요하다 (화면에는 "자가입력·미확인"으로 표시됨).
- 정답 기업(분야가 맞는지)은 한 사람이 정했다. 공고 담당자 2~3명이 따로 고른 정답과 비교해야 한다.
- 공고가 5건뿐이라 기업 → 공고 방향 순위는 재지 않았다.
- 보완질문 답(TRL, 보안측정)은 DB 에 넣지 않고 측정 때만 쓴다.

## 남은 일

- bge-m3 로 순위 재측정: `.env` 에 `EMBEDDER=bge_m3` (`pip install -e ".[bge]"`, 모델 약 2GB 내려받기) 후 `python -m app.reembed`, `python -m app.navigator_eval eval`. 클라우드 개발환경은 모델 저장소 접속이 막혀 못 쟀다.
- 실제 공고(기업마당 수집분) 몇 건에 요건을 넣고, 담당자가 고른 적합 기업과 비교
