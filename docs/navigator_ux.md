# Navigator 화면 기준

기업 화면과 담당자 화면에서 무엇을 보여 주고 무엇을 숨기는지 정리한 문서.

## 사용 흐름

**기업 담당자** (로그인 없음)

1. `/navigator` 에서 사업자번호 조회 → 공개 정보로 판정한 공고 목록
2. '회사 정보 입력·수정' → 등록 이메일로 온 확인 코드 6자리 → `/navigator/manage`
3. 지원 가능 공고 탭: 지원 가능 / 확인 필요 / 지원 어려움(접힘). 확인 필요 공고는 카드 안에서 바로 답하고 다시 판정
4. 회사 정보 탭: 비어 있는 항목을 채우면 저장과 동시에 다시 판정
5. 알림 탭: 등록 이메일은 등록 때부터 받는 중. 끄기·분야 조건, 다른 수신자 추가

**기관 담당자** (로그인)

1. `/staff/navigator` 에서 공고 선택
2. 적합 / 확인 필요 / 부적격(접힘) 목록을 관련도 순으로 확인
3. 기업 이름을 누르면 오른쪽 패널에 기업 정보
4. 알림 신청 기업에 공고 알림 발송

## 화면 표기

| 내부 값 | 기업 화면 | 담당자 화면 |
|---------|-----------|-------------|
| ELIGIBLE | 지원 가능 | 적합 |
| NEEDS_INFO | 확인 필요 | 확인 필요 |
| INELIGIBLE | 지원 어려움 | 부적격 |
| total_score | 관련도 높음 / 보통 / 낮음 (경계는 아래) | 관련도 높음 · 61% |
| origin SELF / EXTERNAL / INTERNAL | 직접 입력 / 공공데이터 확인 / 기관 보유 자료 | 직접 입력 / 확인됨 |

관련도 경계는 임베더마다 다르다: hash 높음 ≥0.45·보통 ≥0.25, bge-m3 높음 ≥0.60·보통 ≥0.53 (`services/navigator_embedding.py` `FIT_LEVELS`, `NAVIGATOR_FIT_HIGH`·`NAVIGATOR_FIT_MID` 로 덮어씀). 화면은 시작할 때 `GET /navigator/fit-levels` 로 받는다. 알림 조건의 관련도(`min_score`)도 같은 경계를 쓴다. 임베더를 바꾸면 기존 구독의 `min_score` 는 그대로라 다시 골라야 한다.

## 화면에서 뺀 것

- 총점 소수(0.65), 기준별 가중치(×0.45), IPC 코드: 화면에서 제외. 기업 화면은 점수 없이 라벨만. 담당자 '조건별로 보기'의 관련도 구성은 '높음 · 55%' 처럼 라벨과 값을 함께
- 서버가 만든 판정 문장의 '기술 적합도 0.xx': 판정 문장과 알림 메일에서 제외
- 매칭 모델명, 후보 수 용어, 출처 코드, mock/live, 서버 명령어, X-User-Id
- '관리 링크', '보완질문', '자가입력', '진위확인 값' 같은 내부 용어 → '이메일 링크', '확인 필요 항목', '직접 입력'
- 별도 보완질문 탭: 해당 공고 카드 안으로 옮김

기관 공통 레이아웃의 역할 전환·'이 역할이 할 수 있는 일'은 다른 기능 시연에도 쓰여서 그대로 둔다.

## 점수 표시 (기관 화면 공통)

유사도·적합도는 높음 / 보통 / 낮음 라벨 옆에 값을 퍼센트로 붙인다 (예: '관련도 높음 · 61%'). 기업 화면과 메일은 라벨만 (`components/levels.ts`, 서버 `services/levels.py`).

| 점수 | 경계 | 쓰는 곳 |
|------|------|---------|
| 내용 유사도 (임베딩) | 임베더별, 관련도와 같음 (hash .45/.25, bge-m3 .60/.53) | 신규 과제 기획 관련 과거 과제, 갭 분석 관련도, 문서 검색, 추천 항목 중 기술·환경·사업목적 |
| 비율형 점수 (적합도, TRL, 성능 충족) | 0.70 / 0.50 | 연계 추천 적합도, 검토표 적합도, 추천 항목 중 TRL·성능 |

- 연계 추천 이유(규칙 문장)와 갭 사유 문장에도 수치를 넣지 않는다. 이미 저장된 추천·갭은 다시 돌려야 새 문장이 된다.
- 엑셀 내보내기(검토표)는 분석용이라 점수를 숫자로 둔다.
